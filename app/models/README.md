# ¿Cómo colaborar?

La colaboración en este proyecto debe seguir ciertas pautas para garantizar la coherencia del código y evitar problemas de integración entre los miembros del equipo.

## Reglas generales

- **No modificar la estructura de los modelos sin previa autorización del equipo.**
- Cualquier cambio relacionado con:
  - Tablas o entidades del sistema
  - Atributos o tipos de datos
  - Relaciones entre modelos
  - Enumeradores dentro de las clases
  - Funcionalidades críticas relacionadas con la base de datos  
  debe ser comentado y aprobado por el grupo antes de ser implementado.

## Flujo sugerido para cambios

1. Proponer el cambio mediante un mensaje en el canal acordado (por ejemplo, en el grupo del equipo o issue del repositorio).
2. Esperar la revisión y aprobación del equipo.
3. Una vez aprobado, realizar la modificación correspondiente.
4. Notificar que el cambio fue aplicado.

## Buenas prácticas

- Utilizar ramas separadas para nuevas funcionalidades o cambios.
- Hacer commits descriptivos.
- Verificar que el proyecto ejecuta correctamente antes de hacer un pull request.
- No subir carpetas de entornos virtuales ni archivos generados automáticamente.

## Importante

> **Ningún aspecto del modelo debe ser modificado de manera particular o unilateral. Cualquier cambio debe ser acordado previamente por el grupo.**
